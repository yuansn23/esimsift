## 4. 为什么既有守卫全绿却漏了

| 守卫 | 为什么不报 |
|---|---|
| `verify_de_text.py` **E1–E5** | 只扫「套餐名单元格」与「整页可见文本」，而整页可见文本**先挖掉 `<script>`** |
| `verify_de_text.py` **F** | 黑名单（短语 23 条 + 词 8 条）—— `Pick two providers` / `Our pick` / `No plan matches` 都不在名单里。其 docstring 自己写着「F 清单永远追不上数据」 |
| `verify_de_text.py` **G** | 清单来自「**已进 `strings.toml` 的数据串**」—— JS 硬编码文案不是数据层字符串，G 天然看不见 |
| `check_i18n.py` 内联脚本判据 | ① 只 `warns.append`（**WARN，不失败构建**）；② 正则 `["'`]([A-Z][A-Za-z][^"'`\n]{12,})["'`]` 要求字面量 ≥14 字符 → `'Compare '`（8 字符）**静默漏报** |
| `_de_link_leak_audit.py` [1] | 读**产物 HTML 的 `<a href>`**；JS 运行时赋值的 href 不在其中 |
| `_de_schema_audit.py` [8] | 只比对**结构化数据**的文本字段；不覆盖普通 JS |
| 本轮 `p81_page_audit.py` 属性层 | 我同样挖掉了 `<script>`（正确做法）→ 所以它也是**故意**不覆盖这一层的 |

⇒ **结论：这不是「守卫写错了」，而是「JS 层从来没有人负责」。** 需要新增一条**产物级 `<script>` 内英文字面量**判据（见 §6）。

1. **`' GB'` → `"GB"` 丢空格** —— EN/DE 同时从 `5.00 GB` 变 `5.00GB`。`GB` 既不是英语词也不是路径 ⇒ 属**非受迫改动**，已回原（`' ' + {{ i18n "g_unit_gb" }}`）。
