# eSIM 关键词「自然植入」方案

**日期**：2026-10-08　**依据**：`docs/keywords/google/`（Google 官方通道，11,454 词）
**配套数据**：`kw-placement.csv`（每词 → 主题 → 落点语义位，**零未归类**）
**复算**：`python -X utf8 scripts/kw_place_google.py`

---

## 0. 一句话结论

你点名的这几个页面，**问题不是「词不够」，是「页面缺语义位」**：

- `/compare/singapore/roamic/` 只有 **0 个词** —— 这家品牌在新加坡**没有需求**，不是我们漏采。
- `/compare/singapore/airalo/` **4 个词**、`/compare/japan/roamic/` **4 个词**、`/compare/japan/airalo/` **36 个词** ——
  而且这些词**几乎全是「这家稳不稳」**（review / reddit / not working / erfahrungen），
  **不是「多少钱」**。
- 但子页现有的 5 条 FAQ 全在**购买决策**轴上（价格 / 无限 / 热点 / 网络 / 竞品），
  **一条都不在信任验证轴上**。**这就是错配。**

所以「植入」不是把词塞进现有的句子里，而是**先补出承载它的语义位**（一个新问答、一段新说明），
再用**用户的原话**当问句、用**我们核验过的数据**当答案。

## 3. 五条「自然」的判据（做不到就不做）

1. **一个语义位承载一「簇」词，不是一个词占一个坑。**
   `is esim available in singapore` / `…in japan` / `…in portugal` 是同一个问句的 49 个国名变体 ——
   写成 **1 条模板化 FAQ** 就覆盖 49 页 × N 变体，不要为每国写一段不同的话（那既假又会同质化）。
2. **问句用用户的原话，答案用我们核验过的数字。**
   问句必须是 `Does {brand} work in {country}?` 这种**用户真会打的字面**；
   答案只能来自 `data/plans/*.toml`、`data/carriers.toml`、`data/providers.toml` 里已核对过的字段。
   ⚠ 子页答案里的数字**必须走 `partials/plan-data-label.html`**（`gb=0` 是「无限」的哨兵值）。
3. **答不上来的主题就不要开位。**
   我们没有评论数据、没有 Trustpilot 单一可信分数（分数按地区域名分片，已裁定**只给档案链接不印分**）。
   所以「review / reddit」类词的做法是 **如实交代我们的核验口径 + 给官方入口**，
   **绝不编一句「用户评分 4.5/5」**。宁可只覆盖词面、把答案写得更有用。
4. **德语词只去德语页。**
   143 个德语词（`erfahrungen` / `aktivieren` / `funktioniert nicht` / `günstig`）
   **不能在英文页硬塞** —— 那既是不自然的文案，也是 Google 眼里的语言不一致。
5. **不新增页型。**
   城市词（965）并国家页小节、区域词（1,273）并现有区域指南 ——
   `keyword-map.md` 的城市页禁令与「新页型需点头」的规矩都不动。

### 4.3 品牌×国家子页 `/compare/{country}/{brand}/`（400 页 · 1,481 词）★ 缺口最大

**现状**：11 个区块 + FAQ **5 问**（价格 / 无限 / 热点 / 网络 / 竞品）。
**问题**：**55% 的词在验证轴，零承接。**

**做法：在现有 FAQ 后追加 4 问（数据驱动，不写套话）**

| # | 问句（承接词面） | 答案（承接事实） | 覆盖主题 / 词数 |
|---|---|---|---|
| Q6 | `Does {brand} have good reviews for {country}?` | 如实说明：**我们不出评分** —— 评论散在应用商店 / Reddit / Trustpilot，且**分数按地区域名分片**（同一家在不同区域是不同值），给单一分数就是不实。我们给的是别人不写的数字：本页实测的 **$/GB、$/day、FUP 阈值、在该国 {total} 家品牌里的价格排名**；想看口碑原文给**官方站点 + Trustpilot 档案**链接 | 验证·评价（529） |
| Q7 | `Does {brand} eSIM actually work in {country}?` | 用 `#hostnetwork` 的真实宿主网络 + 该国 5G 状态回答「能连上哪个网」；再列**三个最常见的失败原因**（手机被运营商锁 / 那条 eSIM 线的数据漫游没开 / 装好但没切到该线路），并指向品牌官方支持 | 验证·可用性（235） |
| Q8 | `How do I activate {brand} in {country}?` | 通用流程（购买 → 收 QR/激活码 → 设置里 Add eSIM → 落地切换）+ 用本页档位说「{n} 天档适合你的行程」；具体机型步骤给品牌官方指南 | 使用·激活（9）+ 光板词里的 how-to |
| Q9 | `{brand} eSIM and VPN in {country}` | **只在中国 / 中国香港等受限网络子页渲染**，用 `countries.toml` 的 `quirks` 已有措辞 | 场景·VPN（136） |

**外加德语页专用（43 词）**：`/de/compare/{country}/{brand}/` 加
`Erfahrungen mit {brand} in {country}` / `Wie aktiviere ich {brand}?` 两条，
**内容与英文页不同源**（不是翻译腔），因为德语用户的搜索词本身就是这两族。

## 5. 排序：热度定「做哪一类」，综合分定「一类里做多少变体」

这是本轮最容易做错的地方，直接给判据：

| 尺子 | 回答什么问题 | 怎么用 |
|---|---|---|
| **相对热度**（`kw-trends-index.csv`） | **这一类值不值得先做** | 只有 10 个词测到非零，前三是 `esim price` / `esim size` / `esim requirements` |
| **综合分**（补全证据） | **这一类里要覆盖多少个句式变体** | 阈值取当次分位数（前 10% = 46.4），**不要写死 60** |
| **`sources`** | **只用来发现词，不用来定序** | `sources` 低 = 「没撒对种子」（`best esim for japan` 只有 1 个种子却是日本页最热的词） |

**具体执行顺序**：

| 批次 | 动作 | 覆盖词 | 依据 | 动基线？ | 需你点头 |
|---|---|---|---|---|---|
| **1** | 首页 FAQ 改 Q1 问句含 `price`；`#price-floor` 小标题含 `eSIM price` | 166 | `esim price` = 0.0619（**最热**） | 首页 2 页 | 否 |
| **2** | 兼容性页加「eSIM size / requirements」两段 | 176 + 172 | 0.0182 / 0.0145（**第 2、3 热**） | 2 页 | 否 |
| **3** | 子页 FAQ 追加 Q6–Q9（模板级） | **1,481**（全族） | 55% 的子页词在验证轴 | **400 页**（属预期变更页型） | **是** |
| **4** | 国家页 `data/faqs/*.toml` 追加 4 问（数据级，49 文件） | ~810 | 可用性 / 口碑 / 设备 / 号码 | 49 页 | 否 |
| **5** | `#verdict` 句式改用 `best eSIM for {country}` | 655 | 唯一测到热度的国家类句式 | 49 页 | 否 |
| **6** | 品牌 Hub 加 `#reviews` 口径说明 | 744 | 未测到热度 | 8 页 | 否 |
| **7** | 区域词并区域指南 / 城市词并 `#quirks` | 2,238 | 未测到热度 | 5 + 49 页 | 否 |

## 6. 落地前必须过的四道闸

1. **`npm run build`**（九项校验全绿）—— 特别注意 `check_i18n.py`（新增文案必须进 `i18n/{en,de}.toml`，
   且 **en/de 逐 key 对齐**）与 `check_headings.py`（h2/h3 **禁用 `,;:—–`**）。
2. **反同质化自证**：新增的子页 FAQ 必须**每页文本唯一** ——
   把该模块在 400 页产物里抽文本算 md5，**去重后必须 = 400**。
   ⚠ 这是硬要求：如果答案里用了 `tagline` / `strengths` 这类**全局字段**，去重后会 < 400。
   所以答案必须填**页内派生量**（该国档位数、最低价、$/GB、宿主网络、价格排名）。
3. **零回归 `--diff`**：预期变更 = `provider_sub 400`（批 3）+ 首页 / 指南 / 国家页 / Hub（批 1、2、4、5、6）；
   **其余页型必须逐字节不变**，变了要按红线 61 做「HEAD 对照实验」再归因。
4. **德语不缺席**：143 个德语词 → 德文页文案**要与英文不同源**（德语用户搜的是 `Erfahrungen`，
   英文页塞这个词是语言错配）。改完 `check_i18n.py` 的 key 数会变 —— 记得重新对齐。

## 7. 不做什么（明确划线）

- ❌ **不为 0 词的页面编内容**（`/compare/singapore/roamic/` = 0 词）：做了就是自欺。

- ❌ **不开城市页 / 不开区域页**：禁令与架构纪律都在。
- ❌ **不在英文页塞德语词**：143 个德语词只去 `/de/`。
- ❌ **不硬凑关键词**：`esim size` 的正确答案是「eSIM 没有尺寸」——**如实回答就自然命中了**，
  不需要在句子里再塞一次。
